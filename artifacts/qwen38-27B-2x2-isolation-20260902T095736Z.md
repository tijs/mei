## Trigger isolation

The two crash cells (A, C) share **in-memory-only paged cache** (`prefix cache
enabled (paged in-memory + no disk)`); both disk-backed cells (B, D) pass
(`paged in-memory + disk`). Prefill step 64 vs 512 makes no difference to the
crash — both steps crash without the disk tier and both pass with it.

**Verdict: the crash trigger is the in-memory-only paged KV cache tier, not the
prefill step size.** Crash signature is identical in A and C:

```
MLX/ErrorHandler.swift:343: Fatal error: SmallVector out of range. at
.../vmlx-swift/Source/Cmlx/mlx-c/mlx/c/array.cpp:335
```

Unexpected-but-verified: prefill step 512 alone (cell C) does NOT rescue the
model; the disk-backed cache tier (`MEI_KV_CACHE_DIR`) is the required
configuration element for this dense qwen3_5 model in the current binary.

## Implication (release risk, unchanged conclusion, now with isolated cause)

Auto-detection routes Qwen3.8-27B-4bit to the GENERIC profile whose current
default has no `--kv-cache-dir`. That specific default crashes this model in the
current binary; the release must either default a disk cache dir into generic or
fix the paged in-memory path. Prefill size is NOT a release lever for stability.
