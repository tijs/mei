## Review findings (this session)

1. Temporal-order parity: 0001's static `temporalOrder` reorder
   (`[..<keep, idx..., keep..<idx]` when wrapped) mirrors the fp16 ring's
   private reorder exactly — the quantized attention span equals the fp16
   span by construction. (Previously verified in session C; re-confirmed
   against the patched working tree.)
2. Dispatch safety: only `KVCacheSimple` + `RotatingKVCache` are replaced
   by `maybeQuantizeKVCache`; `MambaCache`, `CacheList`, `QSAKVCache`,
   TurboQuant paths are skipped by construction. Quantized rings route
   through `updateQuantized` + `quantizedScaledDotProductAttention`
   (AttentionUtils); the fatalError `update` net is unreachable from the
   hot path.
3. Quant determinism (numeric, session C): affine
   quant(dequant(quant(x))) == quant(x) exact (max |Δcode| 0) over
   bits {4,8} x groupSize {32,64,128} x 20 trials; min/max preserved by
   dequant. The 0002 disk design is deterministic by that property.
4. Contracted minor divergence (documented, accepted): quantized ring
   trims to exactly maxCacheSize right after each append; fp16
   updateConcat transiently holds maxCacheSize+S-1 during multi-token
   prefill chunks (<1% window-edge effect at prefill step 512 vs 64K
   ring; prefill-chunk attention only, never decode).
5. 0003 semantics verify against the upstream trace buffer sizing
   (`buffer = promptOffset + maxTokens + 8`): the guard fires only when
   the prefill offset exceeds the threshold, leaving short/medium
   compiled decode intact and eager long-context intact.
6. 0004 keeps generation capacity on `maxKVSize` (only the ring shrinks)
   — attention-bounded probe, memory-bounded by construction.

## NEW pipeline bug found and fixed this session (pre-window)

- run_measurement_cycle.sh phase C passed `--compiled-decode-threshold N`
  to tools/sweep_mei.py, which had NO such argument: the first
  uncontended window running the compiled16 / combined cells would have
  aborted with "unrecognized arguments" (set -euo pipefail). Fixed:
  sweep_mei.py now parses `--compiled-decode-threshold` (0 = no
  threshold), threads it into the server argv, and records
  `compiled_threshold` + `max_kv_window` in each cell's config so
  digest/gate_report render the right columns.
- gate_report.py / summarize_rows.py read cell config via
  `cell.get("config", {})`, but sweep cells carry config at top level:
  tag/kv/window columns printed None. Fixed with
  `cell.get("config", cell)` (tolerates both shapes).
